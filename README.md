# Maple Hunt · 사냥 기록

재획 비약 사용을 화면 인식으로 감지해 사냥 시간, 획득 메소, 솔 에르다 조각, 조각 환산 메소를 캐릭터별로 기록한다. 시세 사이트(maple-market)와 같은 도메인의 **/hunting** 에서 열린다.

| | |
|---|---|
| 주소 | `/hunting` (Next.js `basePath`) |
| 서버 | `127.0.0.1:3200` (이 PC 안에서만 열림) |
| DB | 같은 Postgres의 별도 데이터베이스 `maple_hunt` (`hunt_characters`, `hunt_records`, `hunt_evidence`) |
| OCR | 브라우저 Tesseract.js 7 Web Worker · 한국어/영어 (같은 사이트에서 모델 로드) |
| 조각 시세 | maple-market이 수집하고 `/api/hunting/price`로 받아 온다 |

## 시세 사이트와의 관계

- **조각 시세 수집은 maple-market에만 있다.** 경매장 크롬 확장은 브리지(29171) 하나에만 붙고 검색 횟수도 하루 한도를 같이 쓰므로, 여기서 따로 수집하면 기존 수집과 충돌한다. 이 서버는 `MARKET_URL`(기본 `http://127.0.0.1:3000`)의 `/api/hunting/price`에 오늘 시세와 날짜별 평균가를 묻기만 한다. 시세 사이트가 꺼져 있으면 시세만 비고 기록은 그대로 된다.
- **주소 연결**: 외부 요청은 Cloudflare 터널 규칙이 3200으로 바로 보낸다(설정 시). 이 PC의 `localhost:3000/hunting`과 터널 규칙이 없을 때의 요청은 시세 사이트의 rewrite가 넘겨준다. 어느 쪽이든 원래 호스트는 `x-forwarded-host`로 전달된다. 이 서버는 127.0.0.1에만 열려 있어 외부에서 3200에 직접 접속해 헤더를 속일 수 없다.
- 상단 메뉴는 시세 사이트와 같은 모양이며, 다른 메뉴는 시세 사이트 페이지로 이동한다. 사이트 이름은 메인(`/`), 시세 기록은 `/market`으로 간다.
- 라이트·다크 테마는 시세 사이트와 같은 토큰과 같은 저장 키(`localStorage` `theme`)를 쓴다. `src/app/globals.css`, `src/lib/theme.ts`, `src/components/ThemeToggle.tsx`, `src/components/BrandMark.tsx`는 maple-market의 복사본이라 함께 고친다.
- 화면 배치: 제목 오른쪽의 작은 패널에서 캐릭터 로그인, 왼쪽 열에 스캔 화면과 현재 사냥, 오른쪽 열에 사냥 순서와 조각 시세, 아래에 합계와 기록 목록.

## 사용 순서

1. **캐릭터 로그인**: 캐릭터명과 비밀번호를 넣는다. 처음 쓰는 캐릭터면 비밀번호를 한 번 더 받아 등록한다. 그 캐릭터의 기록은 이 비밀번호로만 보고 더할 수 있다. 로그인은 이 탭에서만 유지되고(24시간) 비밀번호 원문은 어디에도 저장하지 않는다.
2. **게임 설정**: 메이플 설정에서 버프 표시 방식을 **분+초**로 바꾼다. 남은 시간이 분과 초로 보여야(`29분 59초`, `29:59`, 2시간 비약은 `119:59`도 인식) 30분/2시간 비약을 구분해 자동으로 시작한다.
3. Chrome/Edge에서 **스캔 시작**을 누르고 메이플 창을 선택한다. 최초 실행은 한국어·영어 모델을 받아 잠시 준비한다. 이후 선택한 화면을 브라우저 안에서 인식한다.
4. **영역 지정 없이 자동 인식**한다. 화면 상단의 비약 아이콘과 초 단위 타이머, 인벤토리 아래쪽 메소 줄(메소 동전과 오른쪽 180px의 메이플포인트 P 아이콘), 조각 아이콘을 찾아 읽는다. 메소는 "7451만 5280"처럼 억·만 단위로 읽고, 조각 개수는 OCR이 아니라 인벤토리 개수 글꼴(테두리 픽셀 숫자) 대조로 읽는다. 인벤토리는 기타 탭을 연다. 조각이 여러 칸에 나뉘어 있으면 모든 칸의 개수를 더하고, 한 칸이라도 못 읽으면 합계를 null로 둔다(다른 창에 가려진 칸은 알 수 없으니 조각 칸을 가리지 않는다). 여러 칸 합산은 자동 인식에서만 되고 영역 보정은 한 칸만 읽는다. 조각 개수 대조는 원래 크기(100%) 화면에서만 된다. 자동 인식이 안 되는 배치만 **인식 보정 (선택)**에서 영역을 드래그하고 **저장한 영역으로 인식하기**를 켠다. 기존 보정 설정은 자동으로 활성화하지 않는다.
5. **사냥 전 수량 확인**: 비약을 쓰기 전에 인벤토리(기타 탭)를 열어 메소와 솔 에르다 조각이 보이게 둔다. 화면의 "사냥 순서" 2단계에 수량이 표시되면 닫아도 된다. 확인 후 **3분 안에** 비약을 쓰면 그 값이 시작값이 된다. 놓쳤으면 비약 사용 후 30초 안에 열어도 된다.
6. **재물 획득의 비약 사용(필수)**: 버프가 없는 화면을 두 번 확인한 뒤 재물 획득의 비약(소형·일반)을 쓰면 자동으로 시작한다. 다른 버프로는 시작하지 않는다. 이미 켜진 비약이나 시간 표시가 안 보이면 소형/대형 **사용 보정**을 누른다. 비약이 끝나면 알림이 오고 60초 동안 종료 수량을 기다린다.
7. **직접 입력**: 기록되지 않은(null) 시작·종료 보유량만 현재 사냥 카드 또는 기록 표의 **보정 · 증거 · 삭제**에서 입력한다. 기록된 값은 고칠 수 없고, 직접 넣은 값은 OCR이 덮어쓰지 않으며 "직접 입력 포함"으로 표시된다.
8. **기록 삭제**: 기록 표의 **보정 · 증거 · 삭제**를 펼쳐 **이 기록 삭제**를 누른다. 서버의 기록과 증거 이미지가 함께 지워지며 되돌릴 수 없다(`DELETE /api/records?id=`, 로그인한 캐릭터의 기록만). 이 브라우저의 업로드 대기열과 올릴 증거에서도 빼서 다시 올라가지 않는다. 진행 중인 사냥은 표에 없어 지울 수 없고, 녹화 영상은 녹화 보관함에 그대로 남는다. 다른 기기에서 같은 기록을 고쳐 업로드 대기 중이었다면 그 기기가 다시 올릴 수 있다.
9. **증거 이미지**: OCR은 로컬 처리지만 증거 이미지는 서버에 저장한다. 시작·종료 수량을 읽은 순간의 판독 이미지(찾아낸 영역만, 종류별 최근 3장)와, 비약이 끝나 종료 수량을 확인한 순간의 **전체 화면 스크린샷**(1280px WebP, 약 0.1~0.3MB, 최신 1장)이다. 기록 표의 **보정 · 증거 · 삭제**에서 본다.
10. **선택 녹화**: 화면 연결은 읽기만 하고 녹화하지 않는다(Chrome의 "공유 중" 표시는 녹화가 아니다). "사냥 중 영상 녹화"를 켜면 비약 시작부터 저장까지만 1280px·5fps·0.3Mbps(30분 약 68MB, 2시간 약 270MB)로 녹화하고 이 브라우저에 최근 5개만 남긴다.

## 계산과 한계

- 획득량 = 종료 보유량 − 시작 보유량. 거래·소비·창고 이동은 구분하지 못한다. 한쪽이 없거나 줄었으면 null.
- **조각 환산 = 획득 조각 × 사냥 시작일(한국 날짜)의 조각 시세**, 수수료 차감 전. 그날 경매장 시세가 없으면 직접 입력한 시세를 쓰고, 나중에 경매장 시세가 확인되면 그 값을 우선한다.
- 같은 숫자가 두 번 연속 읽혀야 반영한다. 해상도, UI 크기, 배경, 글꼴에 영향을 받으므로 실게임 화면별 검증이 필요하다. 게임 메모리나 키 입력은 쓰지 않는다.
- 자동 버프 탐색은 화면 상단 30%(최대 300px)에서 공식 아이콘을 여러 배율로 비교한다. 다른 아이콘·테마·배치에서는 영역 보정을 사용한다. 초 단위 남은 시간이 확인되지 않으면 사용을 추정하지 않는다. 로그인한 캐릭터로 기록하므로 캐릭터를 바꿀 때는 스캔을 중지하고 다시 로그인한다.
- 인벤토리·메소·조각 개수·사냥터 인식은 실제 게임 화면(2026-09 KMS, 1920×1080) 캡처로 확인했다. 비약 버프 인식과 30분·2시간 사냥 전체 흐름은 아직 합성 입력으로만 검증했다. 게임 UI가 바뀌면 `public/scanner/icons`의 메소·P 아이콘과 `COUNT_DIGITS`를 다시 떠야 한다. 절전·백그라운드 탭 제한으로 인식과 알림이 늦어질 수 있다.
- 기록은 바뀔 때마다 서버에 올리고, 실패하면 브라우저에 보관했다가 다시 올린다("업로드 대기"). 끊긴 사냥은 중단 기록으로 올리고, 10분 넘게 갱신 없는 진행 중 기록은 "기록 중단"으로 보여준다.

## 기대 메소와 손실률

위컴알 사냥터 추출·등록·갱신은 [사냥터 데이터 안내](docs/hunting-map-data.md)를 따른다. 로그인 후 **공유 사냥터**에서 지역·이름을 검색하고 선택하면 레벨과 1젠 몬스터 수가 채워진다. 6분 예상 마릿수는 그 수의 48배이며, 맵 ID·데이터 버전·당시 계산 수치를 기록에 보관한다.

화면의 **사냥** 탭 아래쪽 **사냥 효율** 카드에서 설정한다. 사냥을 시작하면 그때의 설정이 기록(`plan`)에 함께 저장되어, 다른 기기에서도 기대값·손실률이 보이고 나중에 기록별로 고칠 수 있다. 저장된 기록은 **기록 목록** 탭(`/hunting#records`)에 있다.

카드는 메이플로드 사냥 메소 계산기와 같은 세 칸이다.

- **기본 설정**: 넥슨 API 값. 장비·어빌리티 프리셋 1~3 중 메획이 가장 높은(같으면 드롭이 높은) 것을 자동으로 고르고, 쓸만한 홀리 심볼·팬텀 유니온(공격대원 효과 메획 1~5%)·유니온 아티팩트·그랜드 어센틱심볼 값을 채운다. 고친 값은 자동 불러오기가 덮지 않고, 불러오기 버튼은 덮는다.
- **추가 획득 설정**: 재물 획득의 비약(늘 적용), 유니온의 행운(드롭 +50%)·유니온의 부(메획 +50%), 그리드(섀도어, 메획 +20%)·PC방(드롭 +10%)·챌린저스 사파이어 이상(드롭·메획 +20%).
- **계산하기**: 공유 사냥터·몬스터 검색, 몬스터 레벨·6분 마릿수, 드롭·메획 수동 설정(합계 대신 쓴다), 계산 결과.

```
메소 획득량(최종) = (1 + 합연산 메획) × 재물 획득의 비약 1.2 − 1       (최대 300%)
아이템 드롭률      = 합연산 드롭 + 비약 20%                             (최대 500%)
메소 주머니 확률   = min(100%, 60% × (1 + 아이템 드롭률))               → 드롭률 67% 초과면 100%
마리당 메소       = 몬스터 레벨 × 7.5 × 주머니 확률 × (1 + 메소 획득량) × 레벨 차이 배율
6분 예상 마릿수   = 1젠당 몬스터 수 × 48 (6분 ÷ 7.5초)
처치 수           = 6분 예상 마릿수 × (사냥 시간 ÷ 6분)   또는   실측 6분 마릿수 × (사냥 시간 ÷ 6분)
기대 메소         = 처치 수 × 마리당 메소  (일일 한도의 남은 기본 메소까지)
손실률            = (기대 − 실제) ÷ 기대   (음수면 기대보다 더 얻음)
```

- 규칙은 나무위키 「메이플스토리/재화」와 메이플로드 계산기에서 확인했다(2026-09). 마리당 기본 메소는 레벨의 6~9배 중 평균인 7.5배다.
- **레벨 차이 배율**: 캐릭터 − 몬스터가 ±10 안이면 100%. 캐릭터가 11~20레벨 높으면 1레벨당 2%씩(20레벨 80%), 21~29레벨은 75·69·62·54·45·35·24·16·3%, 30레벨부터 0%. 몬스터가 11~20레벨 높으면 1레벨당 3%씩(20레벨 70%), 21~33레벨은 70%에서 1레벨당 5%씩, 34레벨부터 0%.
- **일일 메소 한도는 메획·레벨 차이를 적용하기 전의 기본 메소로 찬다.** 다 차면 필드 메소가 더 떨어지지 않는다. 같은 날 앞선 사냥이 채운 기본 메소는 실제 획득 메소 ÷ (1 + 메획) ÷ 레벨 차이 배율로 되돌려 계산한다. 한도: 1~99레벨 2,000만 · 100~199레벨 4,000만 · 200~259레벨 8,000만 + 200레벨 초과 5레벨당 500만 · 260~300레벨 1억 5,000만 + 260레벨 초과 5레벨당 1,000만.
- 메이플로드는 결과에 공개하지 않은 보정을 곱해 같은 조건에서 이 사이트보다 약 2% 낮게 나온다(한도까지 걸리는 시간은 같다). 이 사이트는 보정 없이 계산하고, 실제와의 차이는 손실률로 본다.
- 예전 기록(`plan.formula` 없음)은 메획이 비약을 뺀 값이라 계산할 때 ×1.2를 곱하고, 저장된 레벨 차이 배율을 쓰며, 메소 주머니는 당시 방식대로 100%로 본다(당시 드롭률은 스탯창 값이라 사냥 때의 프리셋과 다를 수 있다). 기록의 계산 조건을 고치면 지금 방식(`formula: 2`)으로 바뀐다.
- **넥슨 Open API**: 서버가 `NEXON_API_KEY`로 기본 정보(`/character/basic`), 스탯창(`/character/stat`, 참고용), 장비 프리셋(`/character/item-equipment`의 `item_equipment_preset_1..3`), 어빌리티 프리셋(`/character/ability`), 유니온(`/user/union-raider`), 아티팩트(`/user/union-artifact`), 심볼(`/character/symbol-equipment`), 5차 스킬(`/character/skill?character_skill_grade=5`)을 가져온다. 기본 정보 외에는 실패해도 나머지 값으로 보여주고 못 불러온 항목을 표시한다. 호출은 서버 전체에서 초당 5건으로 제한하고, 같은 캐릭터는 10분간 저장본을 쓴다. 게임 데이터는 평균 15분 늦게 반영된다.
- **스캔 주기**: 한 주기는 약 1.5초다. 전체 화면을 OCR하지 않고(1920×1080에서 한 번에 약 6초) 미니맵 머리글·메소 칸·버프 아이콘 주변·왼쪽 아래 이름 칸만 읽는다. 창이 게임에 가려지면 크롬이 `canvas.toBlob`을 한 번에 약 1초씩 늦추므로 OCR에는 직접 만든 BMP를 넘기고, 5분 넘게 가려지면 페이지 반복 타이머가 1분에 한 번으로 묶이므로 스캔 주기는 전용 워커 타이머로 돈다. 사냥터·수량은 같은 값이 두 번 연속 읽혀야 확정되니 이동 후 약 3초 걸린다.
- **사냥 중 사냥터**: 사냥 중에는 사냥터가 비었을 때, 시작 후 3분 안(비약을 먼저 쓰고 이동)일 때, 목록에 없는 곳(마을 등)에서 목록의 사냥터로 옮겼을 때만 바꾼다. 사냥 중 잠깐 마을에 들러도 사냥터는 그대로다.
- **사냥터**: 자동 인식은 미니맵 머리글에서 지도 아이콘(밝은 테두리 정사각형) 오른쪽의 글자 두 줄을 픽셀로 찾는다(첫 줄 지역, 둘째 줄 사냥터). 지난번 자리 → 화면 왼쪽 위 → 화면 위쪽 절반 순서로 찾으므로 모니터 전체를 공유해 게임 창이 화면 가운데에 있어도 된다. 미니맵을 닫으면 읽을 수 없다. 줄마다 밝은 글자를 검게 이진화해 한 줄씩 OCR한다. 머리글 바탕이 표본보다 밝게 보여도 글자 끝과 이진화 기준을 바탕 밝기에 맞춰 잡는다. 머리글 전체를 OCR로 훑으면 줄 찾기부터 흔들렸다. 공유 사냥터 목록에 한글 한 글자만 다른 이름이 하나 있으면 그 이름으로 맞춘다(예: "잔잔한 해만가 2" → "잔잔한 해안가 2", 숫자가 다르면 다른 사냥터로 본다). 같은 이름이 여럿이면 지역 이름으로 가른다. 보정 모드는 ‘사냥터 이름’ 영역을 지정하면 읽는다. 오독하면 직접 고친다. 사냥터마다 몬스터 레벨·처치 기준·몹 수를 이 브라우저에 기억한다.

## 캐릭터와 비밀번호

- 초대 코드나 허용 목록 제한은 없다. 기록 조회·수정은 기존 캐릭터 비밀번호로 구분한다.
- 캐릭터명은 먼저 등록한 사람이 비밀번호(4~64자)를 정한다. scrypt 해시로만 저장한다. 메이플 계정 비밀번호와 다르게 정할 것.
- 세션 토큰은 비밀번호 해시로 서명하므로 비밀번호가 바뀌면 기존 세션이 모두 끊긴다. 별도 서버 비밀키는 없다.
- 비밀번호 5회 실패 시 그 캐릭터 10분 잠금, 접속 주소별 신규 등록 시간당 5회(프로세스 메모리 기준).
- 외부에서도 캐릭터로 로그인하면 스캔과 시세 요청을 쓸 수 있다. OCR 워커는 접속한 사람의 브라우저에서 실행하므로 서버의 Windows OCR 설치에 의존하지 않는다. 기존 `/api/ocr`는 구버전 호환용이며 새 스캐너에서는 호출하지 않는다.
- 비밀번호 재설정 화면은 없다. 잊으면 `maple_hunt` DB의 `hunt_characters` 행을 관리자가 정리한다.

## 처음 설치 (이 PC 기준, 한 번만)

`maple_hunt` DB와 테이블은 이미 만들어 두었다. 다른 PC로 옮길 때는 `.env.example`을 복사해 `.env`를 만들고 `npm install`, `npx prisma migrate deploy`부터 한다.

1. 빌드: `npm run build` (Google 폰트를 받다가 연결 오류가 나면 한 번 더 실행)
2. 서비스 등록 — 관리자 PowerShell. `npm`이 아니라 `next`를 직접 부른다(npm을 감싸면 중지할 때 자식 프로세스가 남는다).

   ```powershell
   $nssm = "C:\Users\user\AppData\Local\Microsoft\WinGet\Packages\NSSM.NSSM_Microsoft.Winget.Source_8wekyb3d8bbwe\nssm-2.24-101-g897c7ad\win64\nssm.exe"
   $node = (Get-Command node).Source
   $root = "D:\evelopment\maple-hunt"
   New-Item -ItemType Directory -Force "$root\logs" | Out-Null
   & $nssm install MapleHuntWeb $node "$root\node_modules\next\dist\bin\next" "start" "-p" "3200" "-H" "127.0.0.1"
   & $nssm set MapleHuntWeb AppDirectory $root
   & $nssm set MapleHuntWeb AppStdout "$root\logs\web.log"
   & $nssm set MapleHuntWeb AppStderr "$root\logs\web.log"
   & $nssm start MapleHuntWeb
   ```

3. 시세 사이트 적용: maple-market에서 `npm run build` 후 `Restart-Service MapleMarketWeb; Restart-Service MapleMarketWorker`. 시세 사이트의 `/hunting` rewrite와 날짜별 시세 API가 이때 반영된다.
4. (권장) 터널 규칙: `C:\Users\user\.cloudflared\config.yml`의 전체 규칙(`service: http://127.0.0.1:3000`) **위에** 아래를 넣고 `Restart-Service MapleTunnel`. 없어도 시세 사이트를 거쳐 동작한다.

   ```yaml
     - hostname: 19991115.xyz
       path: ^/hunting(/.*)?$
       service: http://127.0.0.1:3200
   ```

## 코드를 고친 뒤 적용

관리자 PowerShell에서 maple-hunt 폴더의 배포 스크립트를 실행한다. 별도 폴더에서 빌드를 마친 뒤 서비스가 새 빌드를 사용하도록 전환한다. 실패하면 기존 빌드를 유지하거나 되돌린다. Windows 기본 PowerShell(5.1)과 PowerShell 7 모두에서 돈다(PowerShell 7이 없으면 `pwsh`는 없다).

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy.ps1
```

서비스는 `.next`가 아니라 마지막 배포 폴더(`HUNT_BUILD_DIR=.next-release-…`)에서 뜬다. 그래서 `.next`에 직접 빌드하고 재시작해도 반영되지 않으니 이 스크립트로 배포한다.

DB 모델을 바꿨으면 빌드 전에 `npx prisma migrate deploy`.

## 점검 명령

```powershell
npx tsc --noEmit --incremental false
npx eslint .
npm test
npm run build
```

개발 서버는 `npm run dev` 후 `http://127.0.0.1:3201/hunting`. 3200은 운영 서비스(MapleHuntWeb)가 쓴다.

`predev`/`prebuild`가 잠금 파일에 설치된 OCR 워커·WASM·언어 파일을 `public/scanner/ocr`로 복사한다. 스캔 중 CDN이나 서버 OCR API는 사용하지 않는다. 자동 인식의 브라우저 통합 점검은 개발 서버의 `/hunting/scanner-check`에서 소형/대형 버튼으로 실행한다. 운영 빌드에서는 404다. 합성 화면의 사냥 시작, 메소·조각 판독, 인벤토리 이동과 닫힘을 검증하며 실제 게임 검증을 대체하지 않는다.

참고: [브라우저 화면 선택 제약](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia), [메이플 공식 아이템 가이드](https://maplestory.nexon.com/Guide/N23GameInformation/Articles/418).
